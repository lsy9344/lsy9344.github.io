의존성 없이 만드는 초경량 브라우저 텍스트 에디터 개발기

May 12, 2026

글을 쓰는 순간만큼은 어떤 방해도 받고 싶지 않았습니다. 수많은 툴바, 복잡한 플러그인, 느린 로딩을 가진 상용 에디터 대신 "오직 텍스트와 생각에만 집중할 수 있는 에디터"를 직접 만들어보기로 결심했습니다.

"Every project produces product and understanding."
(모든 프로젝트는 제품뿐만 아니라 더 깊은 이해를 낳는다.)

1. contenteditable과 Selection API 마주하기

브라우저에서 텍스트 입력을 커스텀하게 다루는 것은 생각보다 까다로웠습니다. div[contenteditable="true"]를 사용하면 풍부한 텍스트 편집이 가능하지만, 브라우저 엔진마다 캐럿(커서)의 위치를 다루는 방식이 미묘하게 달랐습니다. 이 과정에서 window.getSelection()과 Range 객체의 내부 구조를 샅샅이 파헤치게 되었습니다. 

// 커서 위치를 정확하게 복원하는 작은 테크닉
const saveSelection = () => {
  const sel = window.getSelection();
  return sel.rangeCount > 0 ? sel.getRangeAt(0) : null;
};

2. IndexedDB로 브라우저 로컬 자동 저장

네트워크 연결이 끊겨도 글이 유실되지 않도록 IndexedDB를 활용하여 500ms 디바운스(Debounce) 주기로 자동 저장을 구현했습니다. 서버와의 통신 없이도 클라이언트 자체에서 완결된 안전한 저장소를 구축하는 방법을 배웠습니다.

3. 프로젝트가 남긴 교훈

거대한 프레임워크 뒤에 감춰져 있던 브라우저의 날것(Raw) API들을 직접 다루어본 것은 개발자로서의 시야를 완전히 바꿔놓았습니다. 버그가 발생했을 때 두려워하지 않고 브라우저 스펙 문서를 읽어보는 단단한 태도를 얻게 되었습니다.
